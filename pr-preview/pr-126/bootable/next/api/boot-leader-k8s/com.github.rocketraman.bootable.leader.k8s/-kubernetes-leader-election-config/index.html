KubernetesLeaderElectionConfig

data class KubernetesLeaderElectionConfig(val leaseName: String, val namespace: String? = null, val identity: String? = null, val leaseDuration: Duration = 15.seconds, val renewDeadline: Duration = 10.seconds, val retryPeriod: Duration = 2.seconds, val requestTimeout: Duration = 5.seconds, val releaseOnShutdown: Boolean = true, val assumeLeader: Boolean = false, val apiServer: String? = null, val serviceAccountDir: String = "/var/run/secrets/kubernetes.io/serviceaccount", val httpClient: String = "kubernetes")

The settings of KubernetesLeaderElection, decoded from the leader.kubernetes config section. Only leaseName is required:

leader {
  kubernetes {
    leaseName = "entries-leader"
  }
}
Content copied to clipboard

The timings follow Kubernetes's own controllers, and client-go's leader election, which this follows: a leader renews its lease every retryPeriod, and gives up leadership if it hasn't renewed it for renewDeadline; another instance takes over once the lease hasn't been renewed for leaseDuration. So a leader that stops, without releasing its lease, is replaced within about leaseDuration, and there are never two leaders as long as the instances' clocks run at about the same rate.
