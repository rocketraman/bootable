Phase
Link copied to clipboard
interface Phase

A step in the coarse start order: services start phase by phase, in the order of StartOrder.phases, and stop in the reverse order. Any type can be one: an enum's entries are phases as they are, since an enum already has a name. Phases are compared with equals; name is used for messages and the logged start plan.

ScopeFailurePolicy
Link copied to clipboard
sealed class ScopeFailurePolicy

When a coroutine in a service's scope fails, the ScopeFailurePolicy set via AppService.scopeFailurePolicy drives the result. By default, it is StopApplication, since a service failure that is not explicitly handled by the developer puts the system in an unknown state, and in this situation it is better to fail-fast than to remain partially running. Modern cloud systems automatically restart failed pods -- compromised ones keep on going. But users can handle failures explicitly, and request other behavior.

StopSignalHandlerLifecycleController
Link copied to clipboard
class StopSignalHandlerLifecycleController : LifecycleController

This lifecycle controller handles HUP, INT, and TERM signals to the JVM, and stops the application if one of these is received. The signal handler is installed after the app is started, so as to prevent race conditions if an app is terminated while it is still initializing.
