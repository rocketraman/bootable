KtorClientService

class KtorClientService(appConfig: KtorClientsConfig, engine: KtorClientEngine, customizer: KtorClientCustomizer = KtorClientCustomizer.None, defaults: Iterable<KtorClientDefaults> = emptyList()) : AppService

Owns the application's Ktor HttpClients, and closes them, and their engines, when the application stops.

There is a default client, and one for each of KtorClientsConfig.named, by name: see get and getOrDefault. Each is Ktor's own HttpClient, built on an engine from engine, with the typed settings of its KtorClientConfig applied through Ktor's own plugins: HttpTimeout for the timeouts, DefaultRequest for the base URL, and HttpRequestRetry for retries, and a plugin of its own for the default headers. Then customizer adds whatever else the application wants, such as ContentNegotiation. Modules can contribute named clients' default settings with defaults, which the application's own settings in appConfig override: see KtorClientDefaults.

val clients = KtorClientService(binder.config("http.client"), CioClientEngine())
val github = clients["github"]

The clients are built when this is constructed, so they can be handed to other components right away, and a bad setting, such as an unreadable key store, fails the application at boot.

The service is in the DefaultPhase.Infrastructure phase, so services that make calls, in later phases, stop before the clients close, and an in-flight call isn't cut off. It provides HttpClientMilestones.ClientsReady, for anything in the same phase that must start after the clients and stop before them.
