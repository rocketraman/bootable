MysqlConfig

data class MysqlConfig(val host: String = "localhost", val port: Int = 3306, val database: String, val username: String? = null, val password: Masked? = null, val sslMode: MysqlSslMode? = null, val allowPublicKeyRetrieval: Boolean? = null, val connectTimeout: Duration? = null, val socketTimeout: Duration? = null, val rewriteBatchedStatements: Boolean? = null, val cachePrepStmts: Boolean = true, val prepStmtCacheSize: Int = 250, val prepStmtCacheSqlLimit: Int = 2048) : JdbcConfig

A strongly typed JdbcConfig for a MySQL database, connected to with MySQL Connector/J, which this module brings in. It brings Flyway's MySQL database module too, for boot-db-flyway.

Its defaults turn on Connector/J's client-side prepared statement cache, sized as HikariCP recommends: the driver otherwise parses every statement again each time it is prepared.

Decoded from the db.jdbc config section:

db {
  jdbc {
    host = db.example.com
    database = app
    username = app
    password = ${?DB_PASSWORD}
    sslMode = VERIFY_IDENTITY
  }
}

The settings other than the address and credentials are passed to the driver as connection properties. Those left null keep the driver's default. For a server address this can't express, such as several hosts for failover, use JdbcGenericConfig with a JDBC URL instead.
