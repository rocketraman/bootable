DbSchedulerService

class DbSchedulerService(dataSource: DataSource, config: DbSchedulerConfig = DbSchedulerConfig(), tasks: Collection<Task<*>> = emptyList(), customizer: DbSchedulerCustomizer = DbSchedulerCustomizer { }, serializer: Serializer = KotlinxSerializationTaskDataSerializer(), clock: Clock = Clock.System, jdbcUrl: String? = null) : AppService

Runs db-scheduler's Scheduler over the application's DataSource, usually the pool of boot-db-jdbc's JdbcDataSourceService: persistent tasks, recurring and one-time, that survive restarts, and that run once across all the application's instances, each execution on whichever instance locks its row first. So, unlike boot-periodic's in-process loops, they need no leader election.

tasks are the tasks it knows: a recurring task, one that is OnStartup, such as Tasks.recurring(…)'s, is scheduled when the scheduler starts, and a one-time task, such as Tasks.oneTime(…)'s, runs the executions the application schedules through scheduler, a SchedulerClient:

val sendReminder = Tasks.oneTime("send-reminder", Reminder::class.java).execute { instance, _ -> send(instance.data) }
val purge = Tasks.recurring("purge", FixedDelay.ofHours(1)).execute { _, _ -> purgeExpired() }
val db = DbSchedulerService(database.dataSource, binder.config("db.scheduler"), listOf(sendReminder, purge))
…
db.scheduler.schedule(sendReminder.instance(reminder.id, reminder), clock.now() + 1.days)

Task data is serialized with kotlinx-serialization by default, by KotlinxSerializationTaskDataSerializer.

It is in the DefaultPhase.Serving phase, as something that brings work into the application, and after DbMilestones.SchemaMigrated, so it starts once its table is migrated and the services its tasks use have started, and stops before them. Shutdown waits up to DbSchedulerConfig.shutdownMaxWait for executing tasks. Creating it opens no connection.

Its table comes from the migrations this module ships for Flyway, in classpath:bootable/db-scheduler/<database>, or the application's own.

Parameters

jdbcUrl

the database's JDBC URL, from which DbSchedulerDialect.Auto picks the dialect; without it, the dialect is detected from the database when the service starts, or, for DbSchedulerPollingStrategy.LockAndFetch, which needs it at once, when the service is created.

clock

db-scheduler's clock, e.g. a fixed one in tests.
