OpenTelemetryCustomizer
Link copied to clipboard
interface OpenTelemetryCustomizer

Adjusts the OpenTelemetry SDK as OpenTelemetryService builds it, after the typed settings of TelemetryConfig are applied. This is how other modules plug into the SDK, e.g. boot-telemetry-otel-prometheus registers its metric reader, and boot-telemetry-otel-gcp adds the GCP resource and authenticates OTLP export to Google. Applications use it for SDK features TelemetryConfig doesn't cover.

ServiceStartTracing
Link copied to clipboard
class ServiceStartTracing(openTelemetry: OpenTelemetry, clock: Clock = Clock.System) : LifecycleController

A LifecycleController that traces the application's start as one trace: a root span, start application, with a child span for each service's start, named start and the service's name, such as start FlywayMigrationService. What a service does as it starts is traced within its span, such as the queries of a database migration, traced by boot-db-jdbc-otel. A start that throws has the exception recorded on its span, with an error status, and so does the root span, when that stops the application's start.

excludeUrlPathsFromTraces

fun excludeUrlPathsFromTraces(paths: Set<String>): OpenTelemetryCustomizer

An OpenTelemetryCustomizer that records no trace for a server request to any of paths, such as a metrics scrape or a health check, which would otherwise fill the traces with requests nobody looks at. A request is matched by its url.path, exactly. Other requests are sampled as before.

fun telemetryConfig(binder: ConfigBinder, env: Map<String, String> = System.getenv()): TelemetryConfig

Decodes TelemetryConfig from the telemetry.sdk config section. When that doesn't set an environment, it is taken from env.environment, the key boot-env reads, if it is set; and when it doesn't set a serviceVersion, from build.version, the key of boot's BuildInfo. The standard OpenTelemetry environment variables, in env, fill in what is still unset; see withOtelEnvironment.
