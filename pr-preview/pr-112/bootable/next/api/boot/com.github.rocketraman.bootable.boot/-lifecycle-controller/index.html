LifecycleController

interface LifecycleController

An interface for controllers for application and AppService lifecycles. For example, such a controller may offer the capability to stop or start services at application start and shutdown, on command, or on demand.

The hooks that may do IO suspend, and run on the lifecycle's own thread, one at a time.

appRunning
Link copied to clipboard
open suspend fun appRunning()

Executed once the application's whole start has completed, including every controller's aroundAppStart, so the application is running. It is called in order of priority, highest first, and not at all if the start failed, or the application began to stop during it. A controller that throws fails the start, as a service that fails to start does, and the controllers after it aren't called.

aroundAppStart

open suspend fun aroundAppStart(serviceContext: ServiceContext, timeline: StartupTimeline, start: suspend () -> Unit)

Runs start, the application's start, with this controller's code around it, such as a span that the whole start runs in. start calls every controller's appStart, so it starts the services, and returns once the application is running, or throws if a service failed to start, or if a stop cancelled the start. An implementation must call start once, and let what it throws propagate.

Runs start, which starts appService, with this controller's code around it, such as a span that the service's start runs in. It is called for each service that is allowed to start (see serviceStartVote), however the start was requested. An implementation must call start once, and let what it throws propagate.

priority
Link copied to clipboard
open fun priority(): Int

The startup/shutdown priority of the controller. Controllers with higher priority are started first, and shut down last. Controllers default to a priority of 0, which means by default startup and shutdown order are undefined. Generally controllers that operate at app startup and shutdown should have a high priority, and controllers that operate at runtime should have a lower priority.

serviceStartVote
Link copied to clipboard
open fun serviceStartVote(appService: AppService): ServiceStartVote

When a service is started, lifecycle controllers may vote on whether it is allowed to start or not. This may be used, for example, for persistently disabling a given service via a controller. Note that, depending on the priority of a controller, a controller may be asked to vote on the start of a service before appStart is called on that controller. This is because a higher priority controller may be attempting to start a service during it's appStart call.
