= Drivers
:description: SQLite, PostgreSQL, MySQL, or any database by JDBC URL.

A driver module supplies the `JdbcConfig`: the database's address, credentials, and driver settings, read from `db.jdbc`.
It brings in the JDBC driver, and `boot-db-jdbc`, so an application lists only its driver.
Choose one; for any other database, use <<any-other-database,a JDBC URL>>.

The typed configs pass their settings to the driver as connection properties.
A setting left unset keeps the driver's default, unless this page says otherwise.

[#sqlite]
== SQLite

`boot-db-jdbc-sqlite` takes the database file's `path`.
Its other settings have defaults suited to a pooled server application, and each is applied to every connection the pool opens:

[source,hocon]
----
db.jdbc {
  path = "./app.db"     # <1>
  synchronous = NORMAL  # <2>
}
----
<1> Names the database file, the one required setting; its directory is created when the application starts.
<2> Makes commits faster, the usual choice with WAL: still safe from corruption, though the latest commits can be lost on power failure.
Unset, SQLite's own, `FULL`, applies.

The others default to what a server application needs, which differs from SQLite's own: `journalMode` is `WAL`, so readers don't block the writer, `foreignKeys` is on, since SQLite ignores foreign key constraints unless each connection turns them on, and `busyTimeout` is 5 seconds, so a connection waits for a lock rather than failing at once with `SQLITE_BUSY`.
`createDirectories` turns off creating the file's directory: see kdoc:boot-db-jdbc-sqlite:com.github.rocketraman.bootable.db.jdbc.SqliteConfig[all the settings].

The pool holds one connection, unless the pool's `maximumPoolSize` says otherwise, since SQLite allows one writer at a time.

[#postgresql]
== PostgreSQL

`boot-db-jdbc-postgresql` takes a `host`, `port`, `database`, and credentials, plus driver settings such as `sslMode`, `currentSchema`, `applicationName`, and the timeouts.
It brings Flyway's PostgreSQL support too.

[source,hocon]
----
db.jdbc {
  host = db.internal          # <1>
  database = notes            # <2>
  username = notes            # <3>
  password = ${?DB_PASSWORD}  # <4>
  sslMode = VERIFY_FULL       # <5>
  socketTimeout = 30s         # <6>
}
----
<1> Where the server is; `localhost` by default, on `port` 5432.
<2> The database to connect to, the one required setting.
<3> Who to connect as.
<4> Keeps the password out of the config file, in the environment; it is `Masked`, so it is kept out of logs and the config report.
<5> Protects against a server impersonating the real one: only `VERIFY_CA` and `VERIFY_FULL` do, and `VERIFY_FULL` checks the host name too.
<6> Bounds every query: the driver otherwise waits forever for a read, such as from a server that went away.

The others are `port`, `currentSchema`, `applicationName`, `connectTimeout`, and `reWriteBatchedInserts`: see kdoc:boot-db-jdbc-postgresql:com.github.rocketraman.bootable.db.jdbc.PostgresqlConfig[all the settings].

[#mysql]
== MySQL

`boot-db-jdbc-mysql` takes a `host`, `port`, `database`, and credentials, plus driver settings such as `sslMode` and the timeouts.
It turns on Connector/J's prepared statement cache, sized as HikariCP recommends, and brings Flyway's MySQL support too.

[source,hocon]
----
db.jdbc {
  host = db.internal          # <1>
  database = notes            # <2>
  username = notes            # <3>
  password = ${?DB_PASSWORD}  # <4>
  sslMode = VERIFY_IDENTITY   # <5>
}
----
<1> Where the server is; `localhost` by default, on `port` 3306.
<2> The database to connect to, the one required setting.
<3> Who to connect as.
<4> Keeps the password out of the config file, in the environment; it is `Masked`, so it is kept out of logs and the config report.
<5> Protects against a server impersonating the real one, by verifying its certificate and host name.

The others include `port`, `connectTimeout` and `socketTimeout`, for which the driver waits forever by default, `allowPublicKeyRetrieval`, `rewriteBatchedStatements`, and the prepared statement cache's: see kdoc:boot-db-jdbc-mysql:com.github.rocketraman.bootable.db.jdbc.MysqlConfig[all the settings].

[#any-other-database]
== Any other database

`JdbcGenericConfig`, in `boot-db-jdbc` itself, takes a JDBC URL, with the driver added as a dependency of its own.
Use it too for an address the typed configs can't express, such as several hosts for failover.

[source,hocon]
----
db.jdbc {
  jdbcUrl = "jdbc:postgresql://db-1.internal,db-2.internal/notes?targetServerType=primary"  # <1>
  username = notes            # <2>
  password = ${?DB_PASSWORD}  # <3>
}
----
<1> The database, and the driver's settings, in the driver's own URL syntax, here two hosts, connecting to whichever is the primary.
<2> Who to connect as.
<3> Keeps the password out of the URL and the config file; it is `Masked`, so it is kept out of logs and the config report.

The others are `driverClassName`, for a driver that doesn't register itself, and `dataSourceProperties`, connection properties passed to the driver: see kdoc:boot-db-jdbc:com.github.rocketraman.bootable.db.jdbc.JdbcGenericConfig[all the settings].

== Change the driver

Swap the driver module for another, in the same flavour, and its config:

[tabs,sync-group-id=di]
======
Vanilla:: Read `PostgresqlConfig`, `MysqlConfig`, or `JdbcGenericConfig` from `db.jdbc`, in place of `SqliteConfig`.
Kodein:: Import `postgresqlConfigModule`, `mysqlConfigModule`, or `jdbcGenericConfigModule`, in place of `sqliteConfigModule`.
Metro:: A driver module's `-metro` artifact contributes its config, so there is nothing to change; for `JdbcGenericConfig`, add `JdbcGenericConfigBindings` to the graph's `bindingContainers`.
Inara:: Pass `PostgresqlConfigSource`, `MysqlConfigSource`, or `JdbcGenericConfigSource` to `jdbcDataSourceModule(...)`, in place of `SqliteConfigSource`.
======
