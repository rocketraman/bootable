= Background work
:description: Loops that poll, persistent tasks that run once across the instances, and a leader to run a loop on one instance.

Bootable has three tools for work the application does in the background, rather than in answer to a request.
Each is an app service, so it starts and stops with the application, in its lifecycle.

* xref:periodic.adoc[Periodic work], from `boot-periodic`: a loop that runs every few seconds or minutes, in the process, such as one that sends the notifications that are pending.
* xref:scheduler.adoc[Scheduled tasks], from `boot-scheduler-db`: db-scheduler's tasks, kept in the application's database, which survive restarts and run once across all the application's instances, such as a reminder an hour from now, or a nightly report.
* xref:leader.adoc[Leader election], from `boot-leader-k8s`: one leader among the application's pods, so a loop runs on one instance only.

The loops and the scheduler are in the `Serving` phase, so they start after the services their work uses, and stop before them.
The leader election is in the `Infrastructure` phase, so the loops know whether they lead when they start.

== Which to use

* For work that polls, such as sending what is pending or sweeping what has expired, use a periodic loop.
Every instance runs it, unless its gate says otherwise.
* For that work on one instance only, gate the loop on the leader, and add leader election.
* For work that must happen once, at a time or on a schedule, and survive a restart, use a scheduled task.
xref:scheduler.adoc[`boot-scheduler-db`] runs them with https://github.com/kagkarlsson/db-scheduler[db-scheduler], which runs each execution on whichever instance locks its row first, so a task needs no leader.

== Modules

Each tool is optional, and its own dependency.
`boot-leader-common`, the `LeaderElection` API, comes with `boot-periodic` and `boot-leader-k8s`.

Every module but `boot-leader-common` comes in `-kodein`, `-koin`, and `-metro` flavours too, for those wiring styles.

modules::background[]

== Install

Add the tools you use, in the flavour of your wiring style.
Leader election calls the Kubernetes API server with one of the application's HTTP clients, so it needs a client engine, here CIO; the scheduler needs a xref:database:index.adoc[database], here SQLite through HikariCP, with Flyway to create its table.

install::[boot-periodic, boot-leader-k8s, boot-client-http-ktor-cio, boot-scheduler-db, boot-db-jdbc-sqlite, boot-db-pool-hikari, boot-db-flyway]

[#with-telemetry]
=== With telemetry

Turn on the *Telemetry* switch, at the end of the tabs above, for the install with telemetry: it adds `boot-telemetry-otel`, the application's OpenTelemetry SDK.
With Kodein, Koin, Metro, or Inara, the loops and the scheduler then trace each run and each execution on their own, through its `OpenTelemetry`; with vanilla wiring, you pass them the tracing.
It turns on the other modules' telemetry too: the pool's metrics, a span for each statement, and the HTTP client's calls to the Kubernetes API server.

xref:periodic.adoc#telemetry[Periodic work] and xref:scheduler.adoc#telemetry[Scheduled tasks] show how to wire the tracing, and how to change or turn it off.

== Example

`examples/server-ktor-db` has a loop that logs the number of entries, on the leader only, and a recurring db-scheduler task that logs a digest of them, each traced.
Its config skips the election, with `leader.kubernetes.assumeLeader`, so it leads when run locally.
It is wired each of the five ways; from the repository root, run yours:

[tabs,sync-group-id=di]
======
Vanilla::
+
[source,shell]
----
./gradlew :examples:server-ktor-db:vanilla:run
----

Kodein::
+
[source,shell]
----
./gradlew :examples:server-ktor-db:kodein:run
----

Koin::
+
[source,shell]
----
./gradlew :examples:server-ktor-db:koin:run
----

Metro::
+
[source,shell]
----
./gradlew :examples:server-ktor-db:metro:run
----

Inara::
+
[source,shell]
----
./gradlew :examples:server-ktor-db:inara:run
----
======

Every minute, it logs `Entry count:` from the loop, and `Entry digest:` from the task.
