= Bootable

image:https://img.shields.io/maven-central/v/com.github.rocketraman.bootable/boot[Maven Central,link="https://search.maven.org/search?q=g:com.github.rocketraman.bootable"]
image:https://img.shields.io/github/license/rocketraman/bootable["GitHub license",link="https://github.com/rocketraman/bootable/blob/HEAD/LICENSE"]

A simple, *unopinionated* framework for booting Kotlin applications.
It handles starting, stopping, lifecycle management, logging, configuration, and other basic reusable components, and then gets out of your way.

*Documentation: https://rocketraman.github.io/bootable/*
For LLMs and other tools, the documentation is also published as Markdown, indexed by https://rocketraman.github.io/bootable/llms.txt[llms.txt].

== Key Differentiators

* *No DI framework in the core.*
Bootable accepts two sets: your application's services and optionally its lifecycle controllers, and how you assemble them is your choice: by hand, with Bootable's optional bindings for https://zacsweers.github.io/metro/[Metro], https://insert-koin.io/[Koin], or, experimentally, https://kosi-libs.org/inara/[Inara], or with any other DI.
Bootable's bindings for https://kosi-libs.org/kodein/[Kodein] are deprecated, as Kodein is.

* *Explicit, not discovered.*
No classpath scanning, no auto-configuration, and no annotations that change what code does: a module does nothing until you wire it explicitly.

* *A lifecycle on coroutines.*
Services start and stop in suspending functions, in phases and after the milestones they declare, and their background work runs in scopes of their own, so concurrency is structured.

* *Libraries, used directly.*
Optional modules set up well-chosen libraries for the common case, and expose their own types rather than wrapping them: Hoplite for configuration, Log4j2 for logging, HikariCP, Flyway, and Exposed for databases, Ktor for HTTP servers and clients, db-scheduler for persistent tasks, and OpenTelemetry for traces and metrics.
Liveness and readiness probes based on the registered services, periodic work, and leader election through a Kubernetes Lease are additional mini-libraries Bootable provides.

* *Testing without booting.*
Helpers for a test clock, captured logs, the start plan, and in-memory telemetry, for fast unit tests with no application booted.

The https://rocketraman.github.io/bootable/[documentation] covers Bootable's philosophy, and how it compares with Spring Boot.

== Quick start

Add the core module:

[source,kotlin]
----
dependencies {
  implementation("com.github.rocketraman.bootable:boot:<version>")
}
----

Implement your services, and boot them:

[source,kotlin]
----
class Greeter : AppService {
  override suspend fun start() = println("hello")
}

fun main() = boot {
  Bootable(setOf(Greeter()))
}
----

`boot` initializes logging, starts the services, runs until the process is signalled to stop, and then stops them cleanly.
Add modules for what your application uses; the https://rocketraman.github.io/bootable/[documentation] covers each, with its code in each wiring style.
